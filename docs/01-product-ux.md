# 产品与交互规范

## 目的

本文档是页面结构、操作流程、默认设置和用户文案的唯一权威来源。实现 UI 时不得根据个人习惯增加步骤、隐藏状态或修改默认行为。网络字段与内部状态以 [网络协议](03-network-protocol.md) 和 [数据与 API](04-data-and-api.md) 为准。

## 前置知识

- 已阅读根目录 [README](../README.md)。
- 理解附近设备、已知设备、我的设备、私聊、群聊、Offer 和待发送任务的区别。
- 知道 Windows 与 Android 的系统行为并不完全相同；具体差异见 [平台行为](05-platform-behavior.md)。

## 产品原则

1. **先选会话，再发送内容。** 操作方式接近常见聊天软件，不提供独立的复杂传输任务首页。
2. **发送立即进入聊天记录。** 即使对方离线，消息也先以“等待对方上线”状态出现在本地。
3. **状态必须可解释。** 用户能区分等待、询问、传输、暂停、完成和需要处理的失败。
4. **主操作不超过两步。** 从附近设备到发送文件最多为“点设备 → 点附件并选择文件”。
5. **不静默覆盖或丢任务。** 重名自动改名；离线任务永久保留；错误提供恢复操作。
6. **PC 与手机保持概念一致。** 导航形态可以不同，但会话、气泡、设置名称和状态文案一致。

## 信息架构

### Windows

主窗口使用两栏布局：

```text
+----------------------------+----------------------------------+
| 会话列表                   | 当前聊天                         |
|                            |                                  |
| [会话] [附近]       [设置] | 标题、在线状态、群成员、更多     |
| 搜索                       |                                  |
|                            | 消息列表                         |
| 会话项 / 附近设备项        |                                  |
|                            |                                  |
| 当前传输 2                 | 输入区、剪贴板、附件             |
+----------------------------+----------------------------------+
```

- 左栏默认宽度 300px，允许在 260-360px 范围拖动；右栏占据其余空间且不得被左栏覆盖。
- 窗口宽度不小于 800px 时显示两栏；640-799px 时使用单栏路由，一次只显示列表或聊天，并在聊天顶部显示返回按钮。
- 窗口最小尺寸为 640×520px；恢复到 800px 以上时回到两栏并保持原会话与滚动位置。
- 左栏顶部固定使用“会话 / 附近”两个 Tab。搜索框只过滤当前 Tab 的会话标题、群名或设备名，V1 不搜索消息正文。
- 点击附近设备后创建或打开私聊，自动切换到“会话”Tab并选中该会话；创建群聊后行为相同。
- 设置齿轮打开独立设置窗口，不占据持久导航列，也不清除当前聊天选择。
- 左栏底部固定显示“当前传输”；有未完成任务时显示数量和聚合进度，无任务时只显示入口。点击后在右栏打开传输任务视图，关闭后恢复此前聊天。
- 关闭主窗口默认最小化到托盘；退出必须从托盘菜单或设置页明确执行。
- 传输任务视图是辅助入口，不取代聊天中的消息气泡。

### Android

底部导航固定为三个入口：

- **会话**：私聊和群聊，按最后活动时间倒序。
- **附近**：当前在线设备和“创建群聊”。
- **设置**：设备名称、接收目录、通知、每设备策略、关于。

进入聊天后使用标准返回键回到原列表；再次进入保持原滚动位置。传输中的前台服务通知可以直接打开对应聊天。

## 首次启动

### Windows

1. 显示设备名称输入框，默认值为系统计算机名，允许修改，长度 1-32 个 Unicode 字符。
2. 显示接收目录，默认 `%USERPROFILE%\Downloads\LAN Chat`。
3. 点击“开始使用”后创建目录、保存设置并启动发现服务。
4. 创建目录失败时停留本页，显示具体路径和“重新选择目录”。

### Android

1. 显示设备名称输入框，默认值为系统可读设备型号，允许修改。
2. 说明“首次接收文件时选择保存目录”，此时不提前弹出 SAF。
3. 请求通知权限；拒绝后仍可进入应用，但传输前必须再次解释前台服务通知用途。
4. 点击“开始使用”后进入“附近”页并启动发现。

不得要求注册账号、输入手机号、扫描二维码或确认安全指纹。

## 会话列表

每个会话项固定显示：

- 私聊设备名或群名。
- 群聊头像由最多四个成员设备名首字自动组合；私聊显示设备类型图标。V1 不支持自定义群头像。
- 最后一条消息摘要。
- 最后一条消息时间。
- 未读数量。
- 如有未完成文件，显示紧凑进度环；不得用进度文字挤占摘要。

摘要规则：

| 消息 | 摘要示例 |
|---|---|
| 文字 | `今晚把照片传一下` |
| 文件 | `[文件] report.pdf` |
| 图片 | `[图片]` |
| 文件夹 | `[文件夹] 相册（128 项）` |
| 剪贴板文字 | `[剪贴板] 192.168.1.20` |
| 剪贴板图片 | `[剪贴板图片]` |
| 系统消息 | `小米手机加入了群聊` |

空列表显示“还没有会话”，下方提供“查看附近设备”按钮。删除会话需要二次确认，只删除本机记录和未完成任务，不通知对端，也不删除已经保存到接收目录的文件。

## 附近设备页

### 页面元素

- 顶部标题“附近设备”。
- 刷新按钮；点击后立即发送发现广播，并旋转最多 3 秒。
- “创建群聊”按钮。
- 在线设备列表：设备名、平台图标、在线状态、关系标记。
- 不显示本机设备。

关系标记只允许：

- 无标记：从未交互的附近设备。
- “已知”：已有会话或接受过内容。
- “我的设备”：完成双方绑定。

点击设备立即创建或打开永久私聊。设备离线后从附近页移除，但已有私聊保留在会话列表。3 秒内未发现任何设备时显示“未发现同一局域网内的设备”，提供“检查 Wi-Fi”和“重新扫描”，不提供公网或蓝牙替代入口。

## 私聊页

### 顶部栏

- 返回按钮。
- 设备名称。
- 在线时显示“在线”；离线时显示“离线，消息将在上线后发送”。
- 更多菜单：设备设置、清空本地聊天记录、删除会话。

### 输入区

- 多行文字输入框，最多 20,000 个 Unicode 字符。
- Enter 发送，Shift+Enter 换行；Android 键盘发送键发送。
- 剪贴板按钮：读取当前剪贴板并显示一次内容预览，用户确认后作为消息发送。
- 附件按钮：文件、图片、文件夹。Android 的“文件夹”通过 SAF 目录选择器完成。
- 空文字不可发送；纯空白按原样保留但至少需要一个非空白字符。

### 消息气泡

- 自己发送的消息靠右，对端消息靠左。
- 连续同一发送者且间隔少于 2 分钟时合并头像与名称。
- 每条气泡包含内容、时间和状态区域。
- 点击文字复制；长按/右键提供复制、删除本地记录。
- V1 不实现撤回、编辑、引用回复和表情回应。

## 群聊

### 创建群聊

入口位于“附近”页。流程固定为：

1. 点击“创建群聊”。
2. 从当前附近设备和已有已知设备中勾选 1-31 台设备。
3. 输入群名，默认由成员设备名拼接生成，用户可修改，长度 1-50。
4. 点击“创建”。本机立即创建群并进入群聊。
5. 每名成员收到群邀请；接受前在创建者成员列表中显示“等待确认”。

同一设备不可重复选择，本机自动成为群主且计入 32 台上限。所有邀请被拒绝时群仍保留，群主可继续邀请其他设备。

### 群邀请

受邀端以应用内对话框和系统通知显示：

```text
电脑-书房 邀请你加入群聊“家里设备”
[拒绝] [加入群聊]
```

- 接受：保存群、成员和群版本，创建系统消息，打开群聊。
- 拒绝：通知群主并删除本地邀请，不创建会话。
- 设备离线：邀请永久排队，双方再次在线时发送。
- 重复邀请：按邀请 ID 去重，不重复弹窗。
- 新成员从接受邀请后的第一条新消息开始接收；V1 不向新成员回填入群前文字和文件。

### 群聊页

顶部显示群名和“在线数/成员总数”。消息气泡在私聊规则上增加发送者设备名。离线成员不阻止在线成员发送；每条发送消息可以打开“送达详情”，查看每位成员的等待、已送达或失败状态。

群主离线时：

- 现有成员仍可发送文字和文件。
- 非群主不能修改群名和成员。
- 群主重新在线后接收期间产生的消息。

### 群资料与成员管理

任何成员可查看群名、自动生成头像、群 ID、群主和成员状态。只有群主显示以下操作：

- 修改群名。
- 邀请成员。
- 移除成员。
- 转让群主。
- 解散群聊。

非群主可以“退出群聊”。退出、移除和解散都需要二次确认：

- 退出：本机停止收发新群消息，保留历史记录；通知群主和在线成员。
- 移除：被移除设备收到更新后停止收发；历史记录保留。
- 转让：目标必须是已接受邀请且当前在线的成员；确认操作后立即生成新群版本，本机失去管理权，更新断线时永久排队。
- 解散：群主发送解散更新；各成员将群标记为已解散并保留只读历史。

群主不能直接“退出群聊”，必须先转让群主或解散群聊。

若群主操作时目标设备离线，成员更新永久排队。群版本冲突的处理由 [网络协议](03-network-protocol.md#群资料同步) 定义。

## 文件、图片和文件夹气泡

### 发送方气泡

固定显示：名称、大小、类型图标、状态、进度条，以及当前状态允许的操作。

| 用户可见阶段 | 可用操作 |
|---|---|
| 等待对方上线 | 取消 |
| 等待对方确认 | 取消 |
| 传输中 | 暂停、取消 |
| 已暂停 | 继续、取消 |
| 已完成 | 打开源文件、在文件夹中显示 |
| 需要重新选择 | 重新选择、取消 |
| 可重试错误 | 重试、取消 |

### 接收方气泡

| 用户可见阶段 | 可用操作 |
|---|---|
| 等待确认 | 接受、拒绝 |
| 传输中 | 暂停、取消 |
| 已暂停 | 继续、取消 |
| 已完成 | 打开、在文件夹中显示 |
| 空间不足 | 更换目录、重试、取消 |

文件夹气泡额外显示文件数量和总大小。图片传输完成后显示缩略图；缩略图必须在传输完成后异步生成，不得阻塞文件数据通道。

### 接收确认

未知设备的首次 Offer 或策略为“每次询问”时显示：

```text
来自 小米手机
3 个项目，共 1.8 GB
将保存到：D:\Users\me\Downloads\LAN Chat
[拒绝] [更改目录] [接受]
```

- Android 尚未设置目录时，“接受”先打开 SAF 目录选择器；用户取消选择则 Offer 保持等待确认。
- 接受未知设备后，将其标记为已知设备。
- 拒绝只拒绝当前 Offer，不拉黑设备。
- 一批文件只弹一次确认，不逐文件弹窗。

## 断点续传和离线显示

- 发送时对方离线：立即创建气泡，显示“等待对方上线”。
- 传输中断网：3 秒内显示“正在重新连接”，确认离线后显示“已中断，等待设备上线”。
- 设备再次上线：自动协商偏移并继续，不再次询问已接受的 Offer。
- 用户暂停：双方都显示“已暂停”；应用重启后保持暂停，不自动继续。
- 源文件变化：显示“源文件已变化，请重新选择”，不得自动重头发送变化后的文件。
- 文件完成：进度必须直接跳到“已完成”，不得长期停留在 100% 的“传输中”。

内部状态转换以 [数据与 API](04-data-and-api.md#传输状态) 为准；本文只规定用户可见表现。

## 剪贴板

### 手动发送

所有私聊和群聊输入区都有剪贴板按钮：

1. 点击后读取当前剪贴板。
2. 支持纯文本和单张图片。
3. 显示预览；点击“发送”后创建剪贴板消息。
4. 不支持的内容显示“当前剪贴板不是文字或图片”。

文字上限 1 MiB UTF-8，图片上限 20 MiB；超过上限时提示改用文件发送。

### 我的设备绑定

入口为私聊右上角更多菜单 → “设为我的设备”。

1. 发起端显示“等待对方确认”。
2. 对端显示“是否将「设备名」设为我的设备”；接受或拒绝。
3. 接受后双方显示“我的设备”标记。
4. 任一端都可以解除绑定；解除后自动剪贴板立即关闭。

绑定只是双方同意关系，不是密码或加密认证。

### 自动同步设置

每个“我的设备”分别配置：

- 关闭（默认）。
- 仅发送。
- 仅接收。
- 双向。

Windows 在应用后台和托盘运行时可以监听并发送。Android 只有应用界面处于前台时自动监听；进入后台后，前台服务通知提供“发送剪贴板”按钮。UI 不得宣称 Android 支持后台自动读取。

自动接收到的剪贴板内容：

- 开启接收时直接写入系统剪贴板，并显示短暂通知“已从「设备名」同步剪贴板”。
- 未开启接收时仍作为聊天消息保存，但不改写系统剪贴板。
- 由远端写入产生的本地剪贴板变化不得再次发送回原设备。

## 传输任务页

用于跨会话查看任务，不提供聊天以外的新状态。顶部筛选：进行中、等待、已完成、失败。每项显示会话、文件名、方向、速度、进度和对应操作。点击任务跳转到所属聊天并定位气泡。

“清理已完成记录”只删除消息中的本地传输详情，不删除接收文件。清理失败或等待任务必须先二次确认，并等价于取消任务。

## 设置页

### 通用设置

- 设备名称。
- 本机设备 ID，只读并提供复制按钮。
- 开机启动（Windows，默认关闭）。
- 关闭窗口时最小化到托盘（Windows，默认开启）。
- 后台保持在线（Android，通知权限可用时默认开启；系统停止服务后仍按离线任务恢复）。
- 通知开关（默认开启）。
- 诊断日志级别（默认“普通”）。

### 接收设置

- 默认接收目录。
- 已知设备默认策略：自动接收（默认）或每次询问。
- 每设备覆盖策略列表。
- 自动打开接收目录：默认关闭。

### 我的设备

列出绑定设备、在线状态和剪贴板方向。支持修改方向和解除绑定。

设置保存失败时恢复旧值并显示错误，不允许 UI 显示新值但核心仍使用旧值。

## 系统通知

| 场景 | 通知标题 | 操作 |
|---|---|---|
| 新群邀请 | `群聊邀请：家里设备` | 拒绝、加入 |
| 需要接收确认 | `小米手机想发送 3 个项目` | 拒绝、查看 |
| 正在传输 | `正在接收 report.pdf` | 暂停、打开聊天 |
| 传输完成 | `report.pdf 已接收` | 打开、显示位置 |
| 传输失败 | `report.pdf 需要处理` | 查看 |
| Android 后台剪贴板 | `LAN Chat 正在保持连接` | 发送剪贴板、暂停服务 |

通知操作必须调用与页面按钮相同的 Rust 命令，不得维护第二套状态。

## 示例

### 群内发送给一名在线、一名离线成员

1. 用户发送 `family.zip`。
2. 本机显示一个群文件气泡和总进度。
3. 在线成员接受后开始传输；离线成员状态为“等待上线”。
4. 在线成员完成后，气泡显示“1/2 已完成”。
5. 次日离线成员上线，发送端仍在线时自动补传。
6. 两名成员均完成后显示“2/2 已完成”。

### Android 在后台发送剪贴板

1. 用户在其他应用复制文字。
2. LAN Chat 处于后台，不能自动读取。
3. 用户展开 LAN Chat 前台服务通知并点击“发送剪贴板”。
4. 系统打开 LAN Chat 的轻量确认页；页面取得焦点后读取并显示预览。
5. 用户点击发送，返回原应用。

## 异常情况

- 对端同名但设备 ID 不同：显示为两个设备，必要时在名称后显示 ID 后四位。
- 群主卸载应用：现有群仍可聊天，但无法管理成员；V1 不自动选举新群主。
- 所有群成员离线：消息保存在发送者本地，逐成员等待上线。
- Android SAF 授权丢失：下一次接收前提示重新选择目录，不静默改到应用私有目录。
- 打开文件失败：保留完成状态，显示“系统中没有可打开此类型文件的应用”。
- 用户取消系统文件选择器：不创建发送消息，不显示失败气泡。
- 选择文件后、数据库提交前应用崩溃：不应出现半条消息；数据库事务规则见数据文档。

- [ ] 所有消息类型都有气泡、摘要、发送入口和错误表现。
- [ ] 离线发送先落库并立即显示，不要求用户等待连接。
- [ ] 群主离线不影响普通群消息。
- [ ] 每个传输状态只显示合法操作。
- [ ] 未知设备首次接收、已知设备自动接收和每次询问均可验证。
- [ ] 我的设备绑定需要双方确认，自动同步默认关闭。
- [ ] Android UI 没有承诺后台自动读取剪贴板。
- [ ] 所有通知操作复用统一命令接口。
- [ ] 删除记录与删除已保存文件严格分离。
