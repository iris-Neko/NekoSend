# 文件粘贴与附件草稿

## 目的

0.4.0 增强输入侧，不修改接收策略、网络协议或 Schema V6。文字和附件依次提交为已有独立消息。

## 前置知识

平台剪贴板可能同时包含文件列表、图片和文字。读取优先级固定为文件列表、图片、文字；纯路径字符串不自动当作文件。

## 规范

- `ComposerController` 按会话持有本次运行的文字与附件。退出不恢复未发送草稿。
- 所有粘贴入口通过 `PasteTextIntent` 或同一粘贴命令进入草稿；选择附件不直接发送。
- 异步粘贴绑定触发会话。文本已变化时不覆写旧选区；删除会话后忽略迟到结果。
- 准备中的附件可取消。附件有错误时先移除或重新添加，不静默跳过。
- 提交前检查可读性和元数据；先文字，再附件。每项保留独立操作 ID；失败停止后续提交并保留剩余项。
- 已入队不代表已送达，网络阶段仍使用原传输状态机。
- 原生读取文件描述，文件内容不通过 MethodChannel/FFI 大数组传递。文件枚举与复制异步执行。
- 临时 URI/门户源固化到应用数据目录 `composer-sources/<session>/<operation>/payload`。提交前写 `.submitted` 标记，避免桥接响应丢失后误删源文件。
- 每个源会话持有 `.lease` 文件锁。只清理确认无活进程持有、且没有提交标记的旧草稿源；已提交源保守保留，供传输恢复和历史预览使用。
- 自动剪贴板同步与手动粘贴分别处理，手动图片以普通 image 消息发送，不自动写入对端剪贴板。

## 平台适配

Windows 读取 CF_HDROP 多文件与 DIB 位图，位图通过 WIC 编码 PNG；原生测试运行在独立窗口站的剪贴板。macOS 读取文件 URL 与图片。Linux 使用 GTK URI 与 FileTransfer Portal，缓存同一剪贴板快照的已解析门户结果。Android 读取前台 ClipData，临时 URI 复制可取消，SAF 选择继续复用持久权限。

## 示例

复制两个文件，在会话 A 粘贴并输入说明，点击发送：说明、文件一、文件二依次入队。若文件二入队失败，草稿只保留文件二，重试不会重新提交前两项。

## 异常情况

权限撤销、源文件变化、路径不合法、剪贴板占用、资源过大或门户失效均保留明确错误。未知 URI、虚拟文件承诺和仅有路径文本不转成隐式文件读取。取消、清理和失败处理不得删除用户原文件。

## 实现检查表

- 四个平台的粘贴快捷键、空文字附件发送、草稿隔离和失败重试有 Flutter 回归。
- Windows 原生多文件、格式优先级、纯路径文字与 PNG 编码有隔离测试。
- Rust 桥接验证异步文件/目录准备及不存在的源。
- 自动测试不覆盖用户真实剪贴板；真机未验收的平台与文件管理器在发布说明中注明。
